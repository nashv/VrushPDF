# 2026-10-13: v1.0.1 (redaction fix)

Follows `2026-10-11-v1.0.0.md`. Also in the history since 1.0.0: the windowed keygen
(`keygen-gui/`, with the issued-keys ledger) and regenerated README screenshots.

## Why

Regenerating the README screenshots showed that redaction, in every version since 0.5.9,
could leave covered text in the file while reporting it excised, and removed text that
wasn't covered. **Documents redacted with 0.5.9–1.0.0 may still contain the redacted
text** and should be redone with 1.0.1.

Bugs in the old `annotations/redact.ts`:

- `TJ` was never examined: the tokenizer emits `[`/`]` as separate tokens and the handler
  scanned from the closing bracket. Most generators write text with `TJ`.
- Text boxes were measured from the baseline *downwards*. A box across a line's middle
  missed it; a slightly tall box hit the line below's measured area.
- Any touched run was removed whole; widths were `length × 0.55em`; the text matrix never
  advanced after a show, so later runs on a line were measured in the wrong place.
- Partly covered images were kept; form XObjects, form field values and the label font's
  resource entry were not handled.

## What it does now

- **Text:** per glyph. Full text state, real widths (`/Widths`, CID `/W` with
  Identity-H, Type3 with `FontMatrix`, and the standard 14 via `@pdf-lib/standard-fonts`,
  now an explicit dependency) and ascent/descent from the font descriptor. `glyphHit`: the
  glyph's horizontal centre must be under a box, and the box must cover ≥15% of the
  glyph's height. Removed glyphs become equal `TJ` displacements, so the rest stays put.
  Fonts without reliable widths fall back to removing the touched run whole (never a
  leak).
- **Images:** removed when fully covered. When partly covered, the covered pixels are
  blanked: raw/Flate 8-bit images in TS, JPEG through `editImage`, which the session
  passes from `pdf/imageEdit.ts` (canvas; it re-encodes as RGB, so the dictionary is set
  to DeviceRGB). Soft masks are blanked too. Undecodable partly covered images (JBIG2,
  CCITT, JPX, predictors) are removed whole, counted in `imagesRemoved`, and the toast
  says so.
- **Also handled:** form XObjects (redacted recursively into per-page copies under new
  names, never altering shared objects), inline images touching a box, painted paths
  wholly under a box (clip paths are kept), annotations, and form field `/V`. The label
  font is registered as `VrushRedactF*`. Original content is wrapped in `q…Q` before the
  boxes.
- **Multi-line text selections:** one box per quad, in the preview (`AnnotLayer`) and
  when applied (`session.applyRedactions`).
- Typed lookups use local `typed`/`typedAt`: pdf-lib's `lookupMaybe` throws on type
  mismatches, which real files are full of.

## Tests

- `verify:roundtrip` "Redaction precision": 17 checks (thin, exact and generous boxes;
  one word with the rest in place; `TJ`; consecutive runs; rotated text; a font without
  widths; raw, JPEG, undecodable and fully covered images; form XObject; paths; field
  value; label font). 134/134.
- `verify:ui` "redaction": a dragged box over one line, and a three-line selection
  redacted from the context menu. 141/141.

## Known limits

- A painted path only partly under a box stays (covered, but its geometry remains).
- Text in CID fonts other than Identity-H is removed in whole runs.
- Document-level text elsewhere (bookmarks, metadata, attachments) is not redacted.
