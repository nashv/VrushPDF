# 2026-10-13: v1.0.3 (toolbar fixes, Reading and Layout menus)

Follows `2026-10-13-v1.0.2.md`.

- **Labels overlapping the tab bar (macOS):** `[data-glass] .row.tools` had
  `height: 44px`, so the rows that wrap since 1.0.2 spilled over the tab bar. It is
  now `min-height`. `verify:ui` checks that, with labels at 1100 px, every toolbar
  button sits above the tab bar under mac+glass, mac, win, gnome and kde. The check
  failed on the old rule, so it guards this.
- **Reading colours never worked** (since 0.5.6): `Viewer.svelte` targeted
  `.page-view`, which no element has. The filters now apply to `.page .canvas` (the
  rendered page, not the annotation overlay), the page background follows, and the
  highlight layer uses `mix-blend-mode: screen` in dark and inverted modes.
- **Menus instead of cycling buttons:** `MenuButton.svelte` (Layout: single / two
  pages / two pages with a separate cover; Reading: normal / dark / sepia / inverted)
  shows the current choice ticked. The menu is portalled to `<body>` with fixed
  positioning so the scrolling top row can't clip it, and has keyboard support.
- Toolbar `.btn-label` rules are `:global` under `.toolbar`, so labels inside child
  components obey the labels setting.

`verify:ui` 155/155.
