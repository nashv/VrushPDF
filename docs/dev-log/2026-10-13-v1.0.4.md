# 2026-10-13: v1.0.4 (button contrast, laser pointer, startup flash)

Follows `2026-10-13-v1.0.3.md`.

- **CI:** the GitHub actions moved to their Node 24 versions (`checkout@v5`,
  `setup-node@v5`, `upload-artifact@v6`, `download-artifact@v7`), which ends the
  "Node.js 20 is deprecated" warning. The CI run was clean. This release is the
  first to use the new artifact actions.
- **Dark text on dark buttons (Windows dark):** `.btn:hover`/`.btn:active`
  (0,3,0) outrank `.btn.primary`/`.btn.selected` (0,2,0), so a filled button lost
  its accent under the pointer but kept its accent text. That text is black only on
  Windows dark (`#000` on `#4cc2ff`), which made it dark on dark (1.8:1). Filled
  buttons now keep their fill and shade it with `filter` (`app.css`).
- **KDE:** white on Breeze's `#3daee9` is only 2.5:1, and the KDE hover rule
  (0,5,0) also removed the fill. Default and checked buttons are now drawn the way
  Breeze draws them: an accent frame and tint, with normal text.
- The tab close × uses `--text-muted` (it was 2.6–2.9:1 in dark).
- **New check, `verify:ui`:** every visible button must have at least 3:1 contrast
  against its real, composited background. It runs on mac, win, gnome and kde, in
  light and dark, at rest and with hover forced via CDP, in the window, with a
  selected tool, with the Reading menu open and in Settings. It waits 250 ms because
  Windows buttons transition their background. Clear the forced hover with the same
  node ids: a new `DOM.getDocument` renumbers nodes and the forced state leaks. Page
  markers (`.page-stack`) are skipped, since they use the annotation colour.
- **Laser pointer stayed on after presenting:** you can exit five ways and none
  reset the laser. An effect in `Viewer.svelte` now turns it off whenever
  `presentationMode` ends, and the dot only renders while presenting.
- **White flash at startup:** the window starts hidden (`"visible": false`). The
  root layout shows it after two animation frames (`core:window:allow-show`
  added). If the frontend never does, `setup` shows it after 3 s. `app.html` also
  has an inline `background: Canvas` with `color-scheme: light dark` (not under
  `data-glass`) for the frames before `app.css` loads.

`verify:ui` 162/162, roundtrip all passed. The flash fix still needs a look in a
real Windows window.
