### Annotation fixes (`fe31625`)

- **Resize handles didn't work** for any annotation, text boxes included. The
  widget layer (`AnnotWidgets.svelte`, z-index 4) sat under PageView's interaction
  surface (z-index 5), so the handles were drawn but never got the pointer. The
  layer is now z-index 7. Its container stays `pointer-events: none`, so only
  handles, note pins and the open text box catch clicks. Handles also got a 17px
  hit area. Side effects: comment pins respond to clicks directly, and clicking
  inside a text box being edited now places the caret.
- **Cursors that follow the theme.** The crosshair, eraser and text cursors are now
  SVG cursors with a contrasting outline (`--cursor-*` variables in `app.css`, with
  a dark-scheme variant). The system crosshair is a thin black line that disappears
  over dark pages and in dark reading modes.
- **Copy and paste of annotations.** `src/lib/annotations/clipboard.ts` plus
  `installClipboard()` in `shortcuts.ts` hook the DOM `copy`/`cut`/`paste` events.
  Those events come from both the native Edit menu items and the keyboard, so text
  copying in fields is untouched. Annotations go on the clipboard under the MIME type
  `application/x-vrushpdf-annotations`, with a plain-text fallback. A held copy covers
  webviews that drop private types. `beforecopy`/`beforepaste` are cancelled so WebKit
  keeps Edit ▸ Copy/Paste enabled. The page context menu also has Copy and Paste Here.
- **Tick and cross tools** (`check`/`cross`, keys C and Shift+C) for form filling.
  `createMark()` in `create.ts` places a vector **Ink** annotation, so no new
  annotation kind was needed and saving and import work unchanged. Mark size reuses
  the `fontSize` style field. Ink is now resizable (`isResizable`, plus an ink branch
  in `scaleAnnotToRect`).
- **Typed sizes.** New `NumberInput.svelte` beside every slider in the toolbar and
  inspector. It commits on Enter, blur or the arrow keys (one undo step), clamps, and
  allows a wider range than the slider (font size 1–200 pt).
- `scripts/verify-ui.ts` has a new "annotation editing" section with 11 checks for
  all of the above, run with real mouse input.

### License keys fixed for good (`01a9ec9`)

**What went wrong:** release 0.5.0 replaced the single public key in
`license_key.pub` (`jQr95…`, this Mac's key) with `udsfDBPO…`, generated on the
other computer. After that, this Mac couldn't issue keys the released app accepts,
and keys from before 0.5.0 stopped working.

**The fix:** `license_key.pub` is now a **list** of trusted public keys, one per
line, with `#` comments. The app accepts a key signed by any of them
(`open_any`/`parse_public_keys` in `license_key.rs`). `build.rs` checks every line.

```
udsfDBPOWStk0iikAi_UtCrLd0WONpZj1L09HXi_IIk  # other computer; the only key in 0.5.0–0.5.10
jQr95iCyOIoYMhQovOJHQzT4SAjefd36U_0Gx7IobtE  # this Mac; releases before 0.5.0, again from 0.5.11
```

Keygen changes:
- `init` now **appends** to the list and never overwrites it.
- `issue` and `check` accept any listed key.
- `check` prints the list and marks which key is this machine's.

Each machine keeps its own `~/.vrushpdf-signing-key`, so back up both.
Run `npm run keygen:check` on the other computer after pulling; its key should show
as listed.

Keys signed on this Mac only activate in **0.5.11 and later**.
